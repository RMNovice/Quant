# 云端开发补充规范 v0.3

日期：2026-11-04。用户已明确采用Codex云端开发。业务范围仍为PRD v0.2，策略Schema仍为1.0.0；本补充仅调整开发环境、交接、验证和交付方式，不要求缩减日线或分钟能力。

## 1. 优先级与环境边界

阅读顺序：本补充 → PRD v0.2 → 开发规格 v0.2 → 数据/API契约 → 开发任务与验收样例 → Schema和示例。本文覆盖相关文档中所有依赖用户Windows本机的工程约定，其他计算与业务规则继续有效。

云端开发、用户浏览器访问网站、网站正式部署是三个不同事项：

- 开发：代码编写、依赖安装、构建、测试均在所选Codex云端环境执行，不要求用户安装Python、Node或数据库。
- 预览：环境支持可访问预览时提供入口，并说明有效期和登录方式；是否支持须实际检查，不预设一定存在。
- 正式运行：持续分钟采集、定时任务、数据库和个人数据需要适合常开运行的托管设施。采用云端开发不等于已选择托管供应商或已授权购买资源。

本机上的文档不会自动成为云端仓库文件；官方说明云端任务只使用其环境内的文件和服务，本机文件与进程不自动转移。[OpenAI官方：开发环境](https://learn.chatgpt.com/docs/environments/modes)

## 2. 交接步骤

1. 将本交接包解压后的根README.md和docs/提交到用于云端开发的仓库；不要只提交压缩包而不解压，也不要只发送C盘路径。
2. 在Codex中选择Cloud及包含该仓库的环境。若尚未准备环境，按当前界面创建、准备并发布可用环境；已有环境直接核对仓库与文件版本。
3. 让云端任务先输出仓库根目录、当前分支/提交标识及实际读到的文档清单，确认包括本补充与策略Schema。
4. 发送同目录的云端开工指令。DEV-01仍是任务编号，定义位于《开发任务与验收样例》；它不是Codex自带命令或必须存在的文件夹。
5. 将开发成果保存到仓库中可审阅的提交或分支；按该环境支持的审阅流程交付。若仓库写权限不足，保留补丁/可下载源码并明确未推送状态，不声称已经同步。

官方云端环境支持基于仓库准备依赖、安装及启动流程，并区分任务工作状态和复用环境；重要成果应保存到版本控制。[OpenAI官方：云端环境](https://learn.chatgpt.com/docs/environments/cloud-environments)

## 3. 工程默认值替换表

| v0.2中的约定 | v0.3云端约定 |
| --- | --- |
| Windows本机启动 | 在实际云端OS中启动，以环境探测结果为准；不得硬编码C盘或假定固定/workspace路径 |
| 必需dev.ps1 / verify.ps1等 | 云端优先提供scripts/setup.sh、dev.sh、verify.sh、backup.sh、restore.sh；Windows脚本成为可选兼容项 |
| 用户先安装Python/Node/Docker | 云端任务检查并配置运行时；锁文件控制版本，用户电脑不作为依赖 |
| 本机Compose启动PostgreSQL | 检查环境支持后使用容器或环境内服务；无Docker则提供可运行的原生PostgreSQL路径，不能默默改SQLite替代撮合/事务验收 |
| localhost为交付访问地址 | localhost只用于环境内部探活；用户可访问入口必须是环境实际提供的预览地址，或经授权的正式部署地址 |
| 仅监听127.0.0.1 | 依平台端口代理需求绑定接口；服务端口不直接对公网开放，预览访问受平台和应用鉴权约束 |
| Windows性能基线 | 记录云端实际CPU、内存、存储和网络；不同于4核/16GB时单列结果，不能把性能目标自动视为已达标 |
| 电脑休眠触发恢复 | 开发任务暂停/环境重建同样要可恢复；正式行情连续运行须在常开部署环境验证 |

前端React/TypeScript、后端FastAPI、独立Python worker、PostgreSQL和行情Parquet的默认架构不变。脚本职责、环境变量和迁移必须可重复执行；不能依赖上一次云端对话中临时手改的状态才能启动。

## 4. 云端DEV-01任务定义

依赖：仓库包含完整文档，云端任务有相应文件读写权限；无行情令牌也能先进行。

输出：

- 仓库工程目录、依赖锁文件、环境配置示例、数据库迁移基础、API与前端最小可运行代码。
- 明确区分demo和real；无数据令牌时进入demo，显示环境标签，不把随机数据落入正式行情表。
- 云端安装/启动/检查脚本、进程日志和停止方式，数据库持久路径与重建说明。
- API的live/ready健康检查，前端可展示环境、API连通和worker状态。
- 开发进度与限制清单，实际执行过的命令、退出结果及源码保存位置。

通过条件：在云端环境内按文档从可复现状态安装并启动前后端和数据库，健康检查成功，demo页面可由环境内部请求；环境支持用户预览时再提供可打开入口。预览能力不存在时，标记“内部运行验证已完成、用户页面浏览待验证”，不能伪造截图或提供用户无法访问的localhost作交付地址。

离线策略回测闭环由后续DEV-04/05/08/09按依赖实现，可以紧接DEV-01推进；不能因为DEV-01工程启动成功就宣称策略或全部网站已完成。

## 5. 网络、凭据与数据验证

包安装域名、行情API、宏观源、数据库地址在环境实际网络策略下逐项验证。某域名被允许并不意味着供应商权限已获得；两个结果分别记录。遇到环境限制，准确说明具体主机或能力，只将受影响任务标为阻塞，继续无依赖开发。

数据令牌通过云端环境的变量/secret能力配置，不提交仓库，不放进前端。环境若提供代理注入凭据，按实际注入方式接入，不要求把原始令牌写入文件；运行所需但未配置的权限在设置页标为缺失。样例.env仅含占位符。

环境准备过程中可以配置依赖安装和服务启动，但任何有费用的行情采购、托管资源创建和正式网站发布，都应先形成具体方案再由用户决定。用户已授权云端开发，常规编写、测试、修复、环境内预览继续推进。

## 6. 验收与生产边界

GOLD-01～12和AC-01～24继续有效；原PowerShell离线验证入口改为`bash scripts/verify.sh --offline`。云端能访问源时再运行真实数据验证；无权限时报告“未验证”，不能用demo补成真实通过。

云端若无法运行浏览器，仍完成API、构建和可运行的引擎验证；人工页面验收或其他受支持环境验证明确列出，不能将未做的视觉验收标为通过。

连续5个A股交易日的分钟采集与模拟对账属于正式运行验收。不能依赖开发任务恰好一直在线，也不能用历史回放替代。开发完成后，根据用户选择的常开环境执行这一阶段。
