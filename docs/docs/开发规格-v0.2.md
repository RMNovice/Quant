# 开发规格 v0.2

本文件与 [PRD v0.2](产品需求书-个人A股量化研究平台-v0.2.md) 一起构成开发基线。以下参数是产品模拟默认值，不是市场推荐参数，也不代表真实券商费率或现行交易规则。

## 1. 工程决策与交付结构

采用模块化单体 API 加独立 worker，不在首版引入微服务。前端 React + TypeScript + Vite；API FastAPI + Pydantic；数据库 PostgreSQL；迁移采用 Alembic；行情用按快照分区的 Parquet；图表用 Lightweight Charts；指标通过共享 Python 实现和固定样例校验。

worker 从数据库持久任务表领取任务，采用行锁、租约和幂等处理；先不增加 Redis。API 只负责校验、排队和查询，CPU 密集回测不在 HTTP 请求或 API 进程内运行。FastAPI 官方也提示重计算宜采用独立任务设施。[后台任务文档](https://fastapi.tiangolo.com/tutorial/background-tasks/) 数据库领取实现可参考 PostgreSQL 的行锁与 `SKIP LOCKED`，但它不替代业务幂等。[官方 SELECT 文档](https://www.postgresql.org/docs/current/sql-select.html)

建议目录（是开发交付要求，目前尚未创建应用代码）：

```text
apps/web/                   页面、路由、组件、API 客户端
services/api/               鉴权、查询、命令、OpenAPI
services/worker/            调度、同步、任务租约、恢复
packages/engine/            指标、规则解释、仓位、撮合、绩效
packages/adapters/          数据源实现和标准化
db/migrations/              数据库迁移与初始元数据
contracts/                  由 docs/contracts 迁入或直接复用的规范
tests/fixtures/             离线行情、规则、公司行为与宏观样例
tests/integration/          API/队列/账本/真实数据可选验证
scripts/                    Windows 启动、停止、检查、备份恢复
docs/                       PRD、运行手册、规则来源、验证报告
data/                       本地行情及快照；不提交大文件和令牌
```

Windows 开发须提供 `scripts/dev.ps1`、`verify.ps1`、`backup.ps1`、`restore.ps1` 和 `.env.example`。数据库可通过 Compose 启动；缺少 Docker 时提供连接现有 PostgreSQL 的说明。默认只监听 127.0.0.1；通过单一源代理 API 与前端。依赖锁文件、数据库版本及安装前提由第一项开发任务固定并记录，禁止每次启动自动升级依赖。

### 2.2 页面统一状态

- `loading`：骨架屏；表格保留列头；超过 10 秒提供重试，不伪报失败。
- `empty`：明确说明“未添加自选 / 无命中 / 数据未接入”等原因并提供对应入口。
- `partial`：展示已有内容、缺失范围、影响功能；不把部分成功当作完整结果。
- `stale`：保留最后值及原时间；禁止依赖其产生新开仓信号。
- `error`：显示可理解的原因、请求 ID 与重试；用户输入保留。
- `unsupported`：显示不支持的证券/规则/权限及替代操作，按钮不假装执行成功。
- `demo`：全局固定标识；正式环境不可将演示结果写入真实数据空间。

未保存离开提示；版本冲突保留本地编辑并提供对比；写请求防重复点击。删除采用归档；被历史运行引用的版本和数据不得物理删除。

图表光标提示时间、OHLC、成交量（股）、成交额（人民币元）、复权模式与输入来源。自选切换股票默认保留周期，重置价格纵轴；报告跳转明确带入历史定位，不悄悄切到最新时刻。

## 3. 条件语言与指标

### 3.1 条件语义

策略版本结构以 [Schema](contracts/strategy.schema.json) 为准。操作数支持常量、已注册字段和指标；每个操作数显式指定周期、参数和偏移。偏移 0 为当前已完成线，1 为前一根有效线；不允许负偏移。根条件组加一层子组，最大 100 个条件、每策略最多 20 个排序因子。

版本创建必须执行Schema以外的语义校验：所有node_id和rule_id各自在策略内唯一；全部条件含覆盖层合计≤100；非空ranking至少一个权重>0；价格与布尔等类型匹配；指标参数完整且匹配注册项；证券/序列/行业ID在对应环境存在；分钟使用session_end有效期、日线使用next_session_end。当前分钟池和历史回测容量在启用/运行时再验证，不能只在保存时校验。图表可显示周/月线，P0策略主决策周期只开放分钟和日线，定期周调仓通过rebalance表达。

支持 `gt/gte/lt/lte/eq/neq/crosses_above/crosses_below`。浮点指标禁止直接 `eq/neq`，相等仅用于布尔、枚举和整数；连续成立由条件的 `consecutive` 参数表示 1～250 根，交叉条件只允许 1。上穿定义：`left[t-1] <= right[t-1]` 且 `left[t] > right[t]`；下穿反之。前后比较均需有效。

三值逻辑：任一比较缺输入得到 UNKNOWN；AND 有 FALSE 即 FALSE，否则有 UNKNOWN 得 UNKNOWN；OR 有 TRUE 即 TRUE，否则有 UNKNOWN 得 UNKNOWN。只有根结果 TRUE 才产生动作。缺输入影响日记保留，不能把 UNKNOWN 当 FALSE 后再用取反绕开限制；P0 不提供 NOT。

候选流程：历史有效股票池 → 基础过滤 → 市场过滤 → 入场条件 → 基础评分 → 风险评分调整并稳定排序 → 新开仓限制及仓位系数 → 仓位分配 → 执行约束。过滤 UNKNOWN 不进入新开仓；持仓退出条件 UNKNOWN 时不凭空卖出，标记 `EXIT_INPUT_UNAVAILABLE`。过滤无效不会覆盖已有仓位的退出规则；计划调仓按第3.3节独立处理。

字段注册表由 `/capabilities` 返回：字段 ID、含义、类型、单位、支持周期、时点模型、权限和参数。初版允许 price OHLC、volume、amount、listing_age_sessions、is_suspended、is_risk_warning、指标及已注册宏观序列。未注册字段和未知参数在创建版本时拒绝，不自动忽略。

跨周期只取当前决策时点已完成且可用的最近线；日线条件读不到当日完整线时使用上一交易日线，并展示对应日期。任何所需操作数无法满足新鲜度时，整体相关条件 UNKNOWN。

宏观操作数的offset按已发布的不同观察期向前移动，不把同一观察期的多次修订计作多期；每期取知识时点可用的最新版本。level取原值，change为本期减上期，return为本期/上期−1；上期为0时return为NULL，指标单位随注册表返回。event.active仅当事件已核验、在所需知识时点可见且未过期/撤回时为TRUE；待核验为UNKNOWN，假设事件仅scenario可读。

### 3.2 指标统一口径

| 指标 | 首版公式及初始化 |
| --- | --- |
| SMA/MA(N) | 最近 N 根有效 close 的算术均值；少于 N 根为 NULL |
| EMA(N) | α=2/(N+1)，首 N 根 SMA 作初值，此后递推；此前 NULL |
| MACD(fast,slow,signal) | DIF=EMA_fast−EMA_slow；DEA 对有效 DIF 按相同 EMA 初值规则计算；柱=2×(DIF−DEA) |
| RSI(N) | 前 N 个价格变动的平均上涨/平均下跌为初值，其后 Wilder 平滑；平均跌为0且涨>0时100，两者均0时50 |
| BOLL(N,k) | 中轨 SMA，标准差使用总体标准差 ddof=0，上下轨=中轨±kσ |
| MOM(N) | close[t]/close[t−N]−1，需要 N+1 个有效价格 |
| VOL_RATIO(N) | 当根 volume / 前 N 根 volume 的平均；不含当前根；分母0时 NULL |
| BREAKOUT(N) | 当根 close > 前 N 根 high 的最大值；不含当前根 |

价格指标采用策略指定的固定复权锚点；volume/amount 保留原始经济单位，不因复权模式切换而重复调整。选择前/后复权但源缺少足够因子时拒绝相应研究，不自动降为不复权。图表浮点计算误差容限 1e-8，账本金额使用十进制。

各模板参数写在可查询的模板 JSON 中，不硬编码于页面：趋势 10/30、量能1.2；动量20、持股10、每周调仓；均值回归 RSI14<30 入场、RSI14>60 或持满10个交易日退出；分钟突破 5分钟、20根高点、量能1.5、日线MA20过滤。它们均为可改的功能初值，默认不启用。

注册表必须校验每个指标所需参数（如SMA必须window，MACD必须fast/slow/signal且fast<slow，BOLL必须window/k），拒绝缺少或多余参数；单位不同的操作数不能比较，cross要求数值且周期可对齐。比较const可由字段单位解释，但界面必须显示单位。所需预热区间内的应交易缺失线不能直接跳过而伪装连续有效；停牌/休市按日历排除，真实缺口应补数或输出UNKNOWN。

### 3.3 排名、目标仓位和多策略

评分因子在已通过过滤及入场条件的同一批候选上做截面百分位：升序平均秩 r，`p=(r−1)/(n−1)`；低值优先用 `1−p`；n=1 或全部相同记0.5。最终得分 `sum(weight*p)/sum(weight)`，权重非负且至少一个>0；缺任一有效因子则该证券评分不可用。无排序因子时使用代码升序。并列得分以证券 ID 升序打破。

首版仓位默认等权，最多 H 只，单股目标为 `min(分配给该策略的目标总仓位/H, 单股上限)`；不足 H 只时保留空余现金，不把资金集中给剩余股票。按排名依次分配，达到行业上限只截断该股目标、不将余额反复分配。历史行业不可用时进入 `UNKNOWN` 行业并受同一上限；设置要求精确行业的策略则拒绝运行。

每账户可分配多个策略，每个策略固定资金比例，和≤1，剩余现金不参与交易；共享实际现金与账本。重复持股按策略分账记录数量和成本，账户层汇总；每个买入批次保留管理版本。策略资产估值包含其现金及持仓；退出释放资金仍归原策略预算。全局风险上限优先于策略上限。

策略换版后旧批次继续由原版本管理；可显式迁移持仓至新管理版本并审计。相同股票同一时点退出优先；仍持仓的同策略股票不叠加买入（计划调仓补差额除外），避免跨策略同时买卖增加成本而失去解释。

`on_signal`每根已完成主周期线判断退出与新入场，保留未触发退出的已有仓位，新候选仅填空缺；不因排名变化自动置换。`daily`在每日最后会话完成且输入可用后重算目标；`weekly`在市场日历中ISO周最后交易日的最后会话后重算。计划调仓选择当时通过全部过滤与入场的前H名，不在目标中的持仓产生REBALANCE卖出，退出约束仍优先；卖不出时保留持仓并占用资金及仓位，不假定已腾出额度。UI显示这种持仓置换语义，交叉入场规则用于定期调仓时给出提示。已有持仓按其管理版本退出；新版本计划调仓默认只管理迁入/新建的批次。

任意固定手工池可作为明确研究范围进行时点回测，但不能声称代表整个历史市场；当前自选快照或当前指数成分选择历史范围时附选择偏差提示。市场筛选池按历史交易所/板块/行业构成，严谨等级仍要求相应历史元数据证据。

### 3.4 风险覆盖的精确定义

动作只允许：`block_new_entries`、`position_multiplier`（0～1）、`score_delta`（−1～1），均在有限股票/行业范围及有效期内生效。

- 系数合并取最小值；无有效系数取1；未知必需输入则禁止新开仓。
- 评分调整按不同规则 ID 相加，再夹到 [0,1]；重复新闻事件按 event_cluster_id 去重，同组同动作只应用一次。
- 新开仓禁止不等于平仓；总仓位下降默认只在后续正常调仓和买入约束应用，不自动新增紧急卖出。
- 首版 `rebalance_on_risk_change=false`，主动减仓功能不暴露为已完成按钮；需要时可由用户显式发起模拟清仓或调仓。
- 若某覆盖层标识为必需而数据不可用，该层不能被自动跳过。用户关闭规则生成新版本；不能直接改历史运行。

证券/行业scope只对匹配目标应用系数，不匹配目标不增加；全局scope才直接缩放总目标。可选覆盖层输入UNKNOWN时跳过该层并给警告，必需层则按前述规则阻止对应范围的新开仓。行业scope的ID包含分类体系和版本，不接受无分类来源的同名行业文本。

## 4. 时间、聚合与数据资格

UTC 为储存与传输标准，`trade_date` 为交易所当地日期。分钟 K 线标准区间为 `[bar_start, bar_end)`，时间戳标识结束时间。会话边界成交按供应商已验证映射写入相邻合法分桶，收盘最后成交归入最后一根；映射版本保存于 snapshot。不凭单条时间字符串推断其开/收标记。

分钟聚合只在相同会话分段内进行，日/周/月按市场交易日历聚合。第一版 A 股默认连续交易分段产生分钟信号，集合竞价信息可展示，但不独立触发策略；日线原始成交口径按供应商定义保留。跨分段剩余长度不足一根时作为较短尾线，标记实际时长；不得补造交易分钟。

### 4.1 三种知识模式

| 模式 | 可用时间 | 可进入何种运行 |
| --- | --- | --- |
| `observed_system` | max(源发布时间/线结束、首次实际获取时间)+计算延迟 | 正向模拟；只承认系统当时确实获取的信息 |
| `historical_replay` | 有证据的历史版本源可用时间+配置传输延迟+计算延迟 | 历史回测；完整性合格才标严格时点 |
| `scenario` | 用户指定假设时点 | 情景实验；永不标严格时点 |

当年历史数据今天首次导入，不以今天的入库时间阻止所有历史回测；使用 `historical_replay`，明确其历史可用时间依据。手工后补事件只有历史来源、修订版本及发布时间证据经核验后，才可新建历史回放快照；不能修改既有运行或伪装系统当时已持有该事件。只知日期的数据保守设为原市场下一交易时段开盘才可用，并标记精度。

宏观值按知识时点取最新已发布 vintage，不按观察期末提前使用。公告日期、事件发生时间、首次发布时间和系统获取时间必须分开。

### 4.2 新鲜度

分钟数据有效阈值=`该周期时长+120秒`，只在市场应交易且证券未停牌时计；已确认休市/停牌不是源故障。日线应在本地可配置的预期发布时间后90分钟内完成，超过则 stale。宏观采用序列发布日历和下一预期发布时间+宽限，而不是一律过24小时判过期；事件只在显式有效期内生效。

阈值可在数据设置页调整并留版本；判断必须返回具体 expected_at、latest_available_at、age 和 reason。策略选用某序列时继承阈值或配置更严格值。

## 5. 撮合和账本确定规则

### 5.1 执行顺序与延迟

每个决策步顺序：导入当时已知数据/公司行为 → 更新可卖数量和估值 → 处理旧委托执行结果 → 已完成线退出/计划卖出 → 新开仓候选和目标 → 资金预留 → 新委托排入合格窗口 → 写入解释链。

`decision_available_at=max(所有输入可用时间)+compute_latency`。首版历史回放默认传输延迟5秒、计算延迟1秒；两者可在运行配置修改，0延迟只允许显式选择并标识“理想基线”。实时模拟以实际到达/计算完成时间为准。

分钟执行窗口为同周期、连续交易会话中第一个 `bar_start >= decision_available_at` 的完整可交易窗口。例如5分钟线09:35结束、09:35:06可用，最早窗口为09:40～09:45，不能以09:35开盘价记账。跨午休或收盘则跳到后续合法窗口；普通新开仓信号有效至当日最后窗口，日末未执行即过期，下一交易日需重新评估。日线信号有效至下一交易会话末；退出条件/止损若仍成立，可重新发出，不长期保留过期委托。

仅有 OHLCV 的正向模拟在执行窗口结束、完整行情到达后确认模拟 Fill；此前状态为 `SUBMITTED`，价格待定。该窗口的 open 为参考价格，加滑点后计算，成交量约束取窗口完整 volume，是延后确认的近似模型，不声称预测可排队量。历史与模拟使用相同窗口模型。休眠恢复后不补发漏过的新开仓及成交，进入数据同步/持仓重估，再从当前时点恢复；历史缺口仅作研究回放。

### 5.2 数量、价格、费用

- 实际证券申报单位、价格步长、交易限制由已核验规则版本提供。测试中的100股单位等只属于合成样例，不能直接作为全部市场规则。
- 买入参考价=`open*(1+slippage_bps/10000)`，卖出反之。按最小价格步长买入向上、卖出向下取整；若调整后超出窗口高低或法定涨跌停边界，保守拒绝成交，不强行夹成有利价格。
- 候选数量取目标金额、可用现金、可卖数量、窗口 volume×参与率的最小约束，按适用申报单位向下取整；零股处理依市场规则，不擅自丢弃持仓。
- 费用以最终成交金额计算：佣金=max(金额×佣金率, 最低佣金)，其他税费分别按适用方向和历史规则计算；每项按人民币分四舍五入（Decimal ROUND_HALF_UP），再求和。
- 首版每笔委托只在一个执行窗口最多成交一次；不足部分取消，不跨窗口追单。买入需按“金额+全部费用”检查现金；数量按申报单位逐档减少至可负担。
- 执行窗口开始前按委托优先级预留预算；窗口结束卖出结算先于同一结算时点买入。不得预支尚未确认的卖出收益；释放预留与成交写同一事务。
- 止损/止盈以批次含买入费用的单位成本为基准，已完成线不复权 close 判断；公司行为调整成本及股数。最长持有期以经过的完整交易日计数，入场交易日为0。

退市以真实可取得的退出/清算数据处理；无数据时冻结不可成交持仓、报告单列残值政策，严格报告不以最后价格自动套现。现金分红区分权益登记、除权和实际到账；到账前为应收，到账后才可买入。公司行为数据不足时冻结受影响计算并指出数据缺口。

### 5.3 绩效口径

组合总资产=现金+应收款+持仓市值−应付款，日末估值。基准采用运行锁定的价格指数或全收益指数，明确类型，不混用。无外部现金流的回测：r_t=E_t/E_(t−1)−1；累计=E_T/E_0−1；年化=(E_T/E_0)^(252/n)−1，其中n为完成的交易日收益观察数。

最大回撤=max(1−E_t/此前峰值)；日波动率用样本标准差 ddof=1×√252；夏普采用日均超额收益/超额日收益样本标准差×√252，无风险年化默认0、可配置，日率=(1+rf)^(1/252)−1。n<2或波动为0时为NULL并给原因，不显示无穷大。

超额收益默认“策略累计−基准累计”（百分点），另列相对净值比但不混称；换手率=期间买入和卖出成交额之和/期间日末平均净资产，明确为双边；胜率只统计完全平仓批次扣费后的正收益数量/完全平仓数量；盈亏比=平均盈利金额/平均亏损绝对金额，无亏损时NULL。部分退出不重复统计胜率。

手工真实持仓如有出入金，净值用时间加权方法分段；第一版回测与自动模拟账户运行中不允许外部出入金，需新建账户以保持口径明确。所有指标都有单位、样本量和 NULL 原因。

## 6. 状态机与操作规则

### 6.1 策略和账户

策略：`DRAFT → VALIDATED_VERSION → ACTIVE → PAUSED → ARCHIVED`。草稿与不可变版本分别建模；PAUSED可重新启用，ARCHIVED仅允许复制。每策略每账户最多一个新开仓版本。ACTIVE切换版本只影响新开仓，旧批次退出仍保留管理版本。

暂停：停止新开仓并取消尚未分配执行窗口的新开仓意图；已提交模拟窗口保留并完成结算，页面显示。退出管理继续。账户 `FROZEN` 则所有新模拟提交暂停；冻结前已提交窗口按原规则结算，不产生回溯取消。用户清仓以独立指令体现并记录。

事件：`UNVERIFIED → VERIFIED → EXPIRED/RETRACTED`，修订新增版本；撤回从系统获知时生效，不改写历史已知快照。情景事件与核验事件不同 namespace。

### 6.2 长任务

`QUEUED → RUNNING → SUCCEEDED / PARTIAL / FAILED`；取消为`QUEUED→CANCELED`或`RUNNING→CANCEL_REQUESTED→CANCELED`。终态不可倒退；部分结果与失败输出不标为正式报告。取消与成功竞争时，以数据库已提交的首个合法终态为准。

worker心跳15秒，租约60秒，单任务默认最多3次尝试（首次加2次重试）；重试退避10/30秒且遵从供应商Retry-After，重试只针对瞬时网络/限频/租约异常，参数和权限错误不重试。前台同时显示本轮和总进度，进度可估计但终态前不显示100%。

并发初值：1个回测、1个同步任务，分钟采集/计算保留专用处理额度，不能被长回测阻塞。任务有效载荷引用快照与版本，不复制令牌。计算超时、配额与供应商频率由能力表控制。

数据修订写新快照；历史报告不自动变动。已发出的信号可标记为输入被修订，但历史成交不删除，另做对照报告。

## 8. 安全、运行与交付

本地首次设置单一管理员密码；密码单向哈希，随机会话，HttpOnly/SameSite cookie；写操作CSRF校验，生产同源策略。访问令牌只由后端读写，用部署环境密钥加密保存，页面回显掩码；备份不含明文密钥，恢复时说明密钥依赖。禁止任意URL代理、任意代码执行和上传任意路径。

导入仅允许有限大小JSON/CSV（默认10MB），先预览校验，按明确证券标识去重，失败逐行报告；CSV导出防公式注入。备份下载需要登录，日志脱敏。远程访问需要单独配置TLS、访问控制与绑定地址，不由本地启动脚本自动开启。

交付包含：可启动代码、依赖锁文件、迁移、样例环境、五个模板、上述脚本、OpenAPI导出、离线/真实数据验收报告、性能记录、备份恢复记录、已知数据与规则限制。新环境按手册启动后能登录并运行一份离线回测；有真实权限时能切换到独立真实环境。
