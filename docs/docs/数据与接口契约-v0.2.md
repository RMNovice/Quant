# 数据与接口契约 v0.2

本文件定义首版模块之间的输入输出。后端据此导出 OpenAPI，前端使用生成类型；未规定的新增字段必须补契约，禁止靠页面猜测第三方响应。策略配置结构见 [JSON Schema](contracts/strategy.schema.json)，业务语义见 [开发规格](开发规格-v0.2.md)。

## 1. 通用约定

- 基础路径 `/api/v1`，JSON UTF-8，字段 snake_case；传输时间为 RFC3339 UTC 字符串（带Z），交易日期 `YYYY-MM-DD`。
- ID 为服务端生成的不透明字符串，证券 ID 为平台稳定标识，不能把供应商代码当主键；同名跨市场证券为不同 ID。示例 ID 仅用于契约说明。
- 金额、价格、费率和权益 API 使用十进制字符串（例如`"10.25"`、`"0.05"`），避免二进制舍入；数量为整数股；指标展示值可用JSON number；缺失为null并附 reason，不用空串/NaN/Infinity。
- 比例为0～1，收益也用小数，页面×100显示%；利差及收益率变动以显式单位bp显示，1bp=0.0001；不得混用“5”和“5%”。
- 列表默认50条、最多200，`items/next_cursor/has_more`；cursor绑定查询条件和排序，同条件相同快照结果稳定。行情批次独立上限2,000根。
- 支持过滤项白名单，排序必带稳定ID作为末位；未知查询参数、未知JSON字段及非法枚举返回422，不静默忽略。
- 任何研究请求显式或由服务器固定 `environment=demo|real`；所有返回带环境。跨环境引用一律409。
- 单条对象包含`id/created_at/updated_at/revision`；修订请求传`expected_revision`，不匹配409；不可变对象无更新接口。
- 写操作需已登录会话与CSRF；请求返回`request_id`，客户端可传`X-Request-ID`，服务端校验格式或生成。
- bootstrap/login为尚未有会话的例外，必须校验同源Origin并限频；其余写操作均使用登录后GET /auth/me取得的CSRF token。
- 创建任务、导入提交、启用策略、模拟清仓等命令必须带`Idempotency-Key`，同账户/路由/键/请求哈希24小时内返回同一结果；键相同内容不同409。成交唯一约束是永久的，不受24小时缓存限制。

统一成功：`{"data":对象或列表,"meta":{"request_id":"...","environment":"real"}}`。删除/归档也返回对象，不混用204。创建资源201；异步操作202并给任务查询路径；普通命令200。

统一错误：

```json
{
  "error": {
    "code": "STRATEGY_VALIDATION_FAILED",
    "message": "短均线窗口必须小于长均线窗口",
    "field_errors": [{"path": "entry.children[0]", "code": "FAST_NOT_LT_SLOW"}],
    "retryable": false,
    "details": {"current_revision": 3}
  },
  "meta": {"request_id": "req_example", "environment": "demo"}
}
```

## 2. 时间与快照字段

| 字段 | 含义与约束 |
| --- | --- |
| event_time | 经济事件/成交实际发生时间，不代表已对外可知 |
| published_at | 源首次发布该版本的时间，未知为null，不能伪造为event_time |
| observed_at | 平台首次取得该版本时间，后续重抓不得覆盖 |
| available_at | 当前知识模式下策略可读时间，按开发规格推导，不让客户端任意回填 |
| valid_from / valid_to | 业务生效区间，左闭右开，valid_to可null；用于行业/规则/状态 |
| vintage_id / revision_id | 宏观、公告或源修订标识；与观察期分开 |
| snapshot_id | 不可变清单ID，清单记录文件哈希、行数、模式、转换版本、日历/规则/来源版本 |
| evidence_level | `verified_timestamp / date_only / inferred / missing`；决定严格回放资格 |

不可变快照清单引用实际不可变Parquet文件和元数据版本；不能仅保存“取数日期”。每次源修订产生新版本。后端返回资格结果`strict_eligible/reasons/missing_ranges`，所有依赖符合才允许严格标签。不同数据源的来源和口径逐项保留。

## 3. 核心数据字典与约束

金额数据库用Decimal/NUMERIC；重要账本金额精确到分，中间价格与成本允许更高精度；禁止数据库FLOAT累计现金。

| 实体 | 必须字段（除通用字段） | 唯一性/关系及约束 |
| --- | --- | --- |
| Security | security_id、exchange、local_code、name、asset_type、currency、listed_on、delisted_on? | ID稳定，代码映射带生效区间；名称不唯一 |
| ProviderSymbol | provider_id、security_id、symbol、valid_from/to | 同provider/symbol时段不重叠 |
| SecurityState | security_id、state_type、value、valid_from/to、available_at、source_revision | 同证券同状态的同版本有效期不重叠 |
| IndustryMembership | security_id、taxonomy_id/version、industry_id、valid_from/to、available_at | 首版每分类体系一个主行业；不可用显式UNKNOWN |
| CalendarSession | market、trade_date、timezone、segments、status、calendar_version | market/date/version唯一，segments含UTC起止和类型 |
| TradingRule | scope、valid_from/to、published_at、tick_size、quantity_rules、price_limit_policy、settlement_policy、evidence_url、verified | 当证券无法匹配已核验规则时拒绝撮合 |
| BarRevision | security_id、timeframe、bar_start/end、trade_date、OHLC、volume_shares、amount、is_final、source_id、source_revision、observed_at | 证券/周期/结束时间/源/修订唯一；历史快照保留原始值 |
| AdjustmentFactor | security_id、trade_date、factor、source_revision、available_at | 因子>0；复权anchor和算法版本归入运行配置 |
| CorporateAction | security_id、type、record_date、ex_date、pay_date、cash_per_share、share_ratio、revision、available_at | 事件修订可追溯，除息与到账分开 |
| MacroObservation | series_id、period_start/end、value、unit、published_at、vintage_id、observed_at、available_at | series/观察期/vintage唯一；无原版数据不冒充历史vintage |
| EventRevision | event_id、cluster_id、title、category、countries、occurred_at?、published_at、observed_at、status、sources[]、valid_until、revision_id | source含URL/机构/核验记录；修订不覆盖已引用版本 |
| Exposure | security_id/industry_id、channel、direction、confidence、evidence_url、valid_from/to、available_at | direction为假设标签，不等同既定收益方向 |
| StrategyDraft | strategy_id、name、description、partial_config、revision | 可不完整；expected_revision乐观锁 |
| StrategyVersion | strategy_id、version_no、config、config_hash、schema_version、validation_result | strategy/version唯一，创建后不可变 |
| StrategyActivation | account_id、strategy_id、entry_version_id、allocation、state、effective_at | 同账户策略唯一活动记录；历史变化审计 |
| Signal | strategy_version_id、security_id、timeframe、bar_end、side、signal_type、inputs_snapshot、decision_available_at、expires_at、explanation | 同运行上下文/版本/证券/周期/线/side/type唯一 |
| Order | account_id、signal_id、intent_type、quantity、window_start/end、state、budget_reserved、rule_version | intent_type为ENTRY/EXIT/REBALANCE/LIQUIDATE；无券商订单ID |
| Fill | order_id、execution_window、quantity、price、fees、settled_at、model_version | order/window唯一；一次成交；与账本同事务 |
| PositionLot | account_id、strategy_id、security_id、entry_version、management_version、quantity、sellable_quantity、cost、acquired_trade_date | 非负；sellable≤quantity；可卖按市场交易日释放 |
| LedgerEntry | account_id、transaction_id、entry_type、amount、currency、lot_id?、action_id?、posted_at | 双重记账或等价可核对的平衡分录；transaction幂等 |
| Task | type、payload_ref、state、attempt、progress、lease_owner/expires_at、heartbeat_at、error、result_ref | 领取后需租约，终态合法迁移；失败保留上下文 |
| Alert / Outbox | dedupe_key、signal_id、payload、delivery_state | dedupe_key唯一；提交事务后异步站内投递 |
| Note | target_type/id、markdown_text、revision | target为股票/策略版本/回测；输出需清理HTML |
| AuditLog | actor、action、target、before_hash、after_hash、reason、occurred_at | 追加写，不含令牌；删除/启停/迁移/数据切换均记录 |

StrategyVersion配置内部严格遵守Schema。其他实体在DB任务中映射成迁移与Pydantic响应模型；以上字段不可因页面暂时不用而省掉时间和来源信息。

## 4. 数据源能力注册与接入协议

每个provider实现：

```text
capabilities() -> ProviderCapabilities
fetch_securities(as_of, cursor) -> Page[RawSecurity]
fetch_calendar(market, start_date, end_date) -> RawCalendar
fetch_bars(provider_symbol, timeframe, start, end, cursor) -> Page[RawBar]
fetch_corporate_actions(provider_symbol, start_date, end_date) -> Page[RawAction]
fetch_macro(series_id, start_date, end_date, vintage?) -> Page[RawMacro]
healthcheck() -> HealthStatus
```

不支持的方法显式返回UNSUPPORTED而非空成功；宏观适配器无需实现股票方法，按capabilities选择。所有网络调用有超时/退避/速率限制，默认单次30秒，任务取消可打断后续批次。

ProviderCapabilities至少包含：资产/市场/周期、允许单位时间调用数及突发上限、单次记录数、实时延迟、历史起点、可缓存范围、权限到期、时间戳标记、成交量单位、是否含集合竞价、复权能力、vintage能力、许可核验状态。

选定数据源后填接入清单：A股日线、当前分钟、历史分钟、涨跌停/停牌、公司行为、证券生命周期、历史成分、国内基准、海外权益、汇率或利率、商品、宏观及日历。每项必须有真实样本、源文档、更新时间、权限结果和缺口。

策略需求100只分钟池时，按供应商实际每请求证券数和请求频率计算容量；预留20%配额用于重试，余下配额不足不得标为READY。图表与后台共享限频器。只读API响应中不得出现令牌。

### 6.2 创建回测

```json
{
  "strategy_version_ids": ["sv_example"],
  "allocations": [{"strategy_version_id": "sv_example", "weight": "1.0"}],
  "date_range": {"start": "2025-01-02", "end": "2025-06-30"},
  "initial_cash": "100000.00",
  "benchmark_id": "idx_domestic_demo",
  "knowledge_mode": "historical_replay",
  "requested_quality": "strict",
  "snapshot_id": "snap_example",
  "ruleset_id": "rules_demo_v1",
  "fee_model_id": "fees_demo_v1",
  "execution_model": "ohlcv_window_v1",
  "source_latency_seconds": 5,
  "compute_latency_seconds": 1,
  "risk_free_annual_rate": "0.0",
  "split": {"in_sample_end": "2025-04-30", "out_sample_start": "2025-05-06"},
  "seed": 0,
  "environment": "demo"
}
```

起止日期包含端点交易日；warmup可早于start但不记收益。样本外指标在同一连续权益路径上截取，明确标注；另起资金运行属于另一个回测。若请求strict但证据不足，返回422及缺口，不自动降级。允许用户改为exploratory后重提；不能把两份请求共用同一幂等键。

运行级ruleset/fee_model覆盖策略默认值时需显式传入，结果保存`effective_config`和`overrides`；多策略使用共同运行模型，参数差异在报告列出。未传时必须从策略默认解析为唯一模型，否则422。source_latency仅用于historical_replay，observed_system使用真实记录不得由用户调成0。示例中的费用/规则ID代表demo元数据，不能用于real。

```json
{
  "data": {
    "run_id": "bt_example", "task_id": "task_example",
    "state": "QUEUED", "status_url": "/api/v1/backtests/bt_example"
  },
  "meta": {"request_id": "req_example", "environment": "demo"}
```

### 6.3 解释结构

每条候选/信号至少包含：`decision_available_at/input_snapshot_id/strategy_version_id/root_result/conditions/risk_actions/target_weight/execution_eligibility`。条件解释包含`node_id/left_value/right_value/operator/result/data_as_of/reason`；不能仅给一段无法核对的自然语言。

示例：`{"node_id":"trend","left_value":10.2,"right_value":10.0,"operator":"gt","result":"TRUE","data_as_of":"2026-11-02T01:35:00Z","reason":null}`。

### 6.4 SSE

事件类型：`task.updated / quote.updated / bar.finalized / signal.created / alert.created / source.health / account.updated / resync_required`。每条携带`event_id/type/entity_id/revision/occurred_at/environment`，不承载大报告或令牌；客户端按event_id去重，按revision防旧事件覆盖。

心跳15秒，服务端保留24小时事件；断线指数退避1～30秒重连并带Last-Event-ID。游标过旧发resync_required，前端重新查询，不声称无缝补齐。多标签页收到相同信号不增加服务器提醒数量。

## 7. 错误与拒绝原因

| HTTP | code | 客户端处理 |
| --- | --- | --- |
| 401/403 | AUTH_REQUIRED / FORBIDDEN / CSRF_FAILED | 登录或提示，保留未保存草稿 |
| 404 | RESOURCE_NOT_FOUND | 对应对象不可用；不泄露其他环境对象 |
| 409 | REVISION_CONFLICT / IDEMPOTENCY_CONFLICT / INVALID_STATE / ENVIRONMENT_MISMATCH | 展示差异或状态并刷新，不盲重试 |
| 422 | STRATEGY_VALIDATION_FAILED / UNKNOWN_FIELD / CAPACITY_EXCEEDED | 定位字段/容量 |
| 422 | INSUFFICIENT_WARMUP / STRICT_PIT_UNAVAILABLE / RULESET_UNVERIFIED | 展示缺口和可运行的研究范围 |
| 424 | DATA_PERMISSION_MISSING / DATA_STALE / DATA_GAP / UNSUPPORTED_MARKET | 指出数据源或规则依赖，禁止假成功 |
| 429 | RATE_LIMITED | 遵从Retry-After，不让页面反复自动请求 |
| 503 | WORKER_UNAVAILABLE / PROVIDER_UNAVAILABLE | 展示最后状态与可重试信息 |
| 500 | INTERNAL_ERROR | 请求ID；不返回堆栈、令牌或数据库连接串 |

逐笔未成交属于业务结果，返回200并包含原因：`T_PLUS_ONE / SUSPENDED / LIMIT_UP / LIMIT_DOWN / NO_LIQUIDITY / INVALID_LOT / INSUFFICIENT_CASH / PARTICIPATION_CAP / PRICE_OUTSIDE_RANGE / SIGNAL_EXPIRED / INPUT_UNKNOWN / ACCOUNT_FROZEN / RISK_BLOCKED`。不可把零成交当任务系统失败，也不可把系统异常吞成无候选。

## 8. 导入导出与兼容

策略导出包括schema_version、配置、来源版本说明，不带系统内部令牌。导入先schema再语义校验，旧schema必须经有记录的迁移；未知版本拒绝，不猜字段含义。

事件CSV至少包括`title/category/published_at/source_url/status`，可补occurred_at、countries、valid_until；无来源默认UNVERIFIED。自选CSV至少为exchange/code，不能只用名称匹配。

成交CSV至少包括run_id、order_id、fill_id、security_id、strategy_version、signal_at、available_at、window_start/end、settled_at、side、quantity_shares、price、gross_amount、各费用、currency、model_version。表头固定、时间格式固定、金额不采用本地千分位。

API新增兼容字段可在同一v1迭代，删除/改名/改变计算语义需新版本或显式迁移。契约变更必须同步Schema、客户端类型、离线样例与相关验收项。
