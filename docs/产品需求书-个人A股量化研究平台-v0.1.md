# 个人 A 股量化研究平台｜产品需求书

版本：v0.1（需求讨论与开发拆分基线）  
日期：2026-11-02  
使用者：个人投资研究者  
本次交付：产品需求与验收标准；尚未开始网站开发、行情采购或部署。

## 1. 产品定位与已确认需求

建设一个自己使用的量化研究网站，以 A 股为主要研究对象，将国内市场、海外市场、美国经济政策与地缘事件放到同一个研究流程中。用户可以在网页上调整策略、比较回测结果、查看选股原因，并在选择个股后进入接近专业行情软件操作习惯的 K 线工作台。

已确认：

- 个人自用，核心市场为 A 股。
- 需要结合全球市场，关注跨市场共振、美国政策和战争等地缘风险。
- 策略规则与参数需要能在前台调整。
- 选择个股后需要查看 K 线图，交互体验参考同花顺。
- 第一版同时需要日线研究与分钟级行情、盘中信号。

本文采用的可调整默认值：桌面浏览器优先；个人单账户；A 股股票做多；先提供研究、回测与模拟持仓；数据预算待定；分钟级先覆盖自选及策略股票池。第一版完整交付必须包含日线和分钟级能力，不能以静态图表或模拟行情替代真实接入后的验收。

核心研究闭环：

**查看市场环境 → 配置策略 → 回测比较 → 生成候选股 → 查看个股及信号 → 模拟跟踪 → 复盘改进。**

产品衡量的是研究流程是否可信、可解释、可复现；不以保证收益作为验收条件。

## 2. 范围与优先级

P0：第一版必须交付；P1：第一版完成后的增强；P2：进一步扩展。

| 能力 | 第一版 P0 | 后续范围 |
| --- | --- | --- |
| A 股行情 | 沪深股票搜索、日线、分钟线、自选股；北交所可搜索和看图，完成规则适配后进入策略池 | ETF 独立交易规则、多资产研究 |
| K 线工作台 | 分时、1/5/15/30/60 分钟、日/周/月线；指标、信号、事件标记 | 高级画线、形态识别、多屏联动 |
| 策略配置 | 表单和条件组，内置模板，版本管理，参数校验 | 自定义表达式、受控代码策略 |
| 回测 | 日线组合回测；有限股票池分钟回测；样本内外对比 | 大规模寻优、滚动训练、更细粒度撮合 |
| 全球联动 | 核心市场指标、跨时区对齐、滚动相关及市场状态过滤 | 多因子归因、更多海外资产 |
| 宏观与事件 | 官方经济日历、事件录入/导入、来源管理、规则化风险覆盖层 | 新闻聚合、AI 辅助提取及审阅 |
| 选股与信号 | 盘后筛选、分钟收盘信号、自选股跟踪、站内提醒 | 用户主动配置后的外部消息推送 |
| 持仓 | 模拟组合及手工持仓记录 | 券商只读同步；实盘接入单独立项 |

第一版不包含：自动向券商下单、Level-2 逐笔盘口、全市场 tick 级计算、多用户社区、策略售卖、原样复制同花顺界面。美国等海外资产第一版用于环境判断，不进入交易撮合。

## 3. 使用场景

### 3.1 盘前：海外变化是否改变今天的计划

用户打开首页，看到上一完整美股交易时段的表现、最新可用的利率/汇率/大宗商品变化，以及今日已公布的宏观日程。系统列出受影响的已启用策略和候选股，说明规则命中原因及数据截止时间。

例如：用户自行配置“原油短期涨幅超过阈值时，降低对燃油成本敏感行业的策略评分”。这是一条待验证的规则；行业影响方向、权重、期限均可修改。

### 3.2 盘中：发现信号并查看个股

股票池内某只股票的已完成 5 分钟 K 线满足策略条件。站内生成去重提醒。点击后进入该股票的 K 线页面，定位对应时刻，展示指标、命中条件、数据延迟、宏观过滤状态和模拟组合中的可卖数量。

### 3.3 盘后：修改参数并比较结果

用户将均线窗口从 20 改成 30，生成新策略版本，分别对同一区间回测。报告比较收益、回撤、换手、成本及样本外表现，保留旧结果并列出参数差异。

### 3.4 地缘风险：检验判断而非直接相信标签

用户录入一条与美伊冲突有关的事件，填写可核验来源、发布时间和预期传导渠道；把相关行业配置为待观察对象，再比较“基础策略”与“基础策略 + 事件过滤”的表现。

本例是产品使用情景，不代表本文对某一具体战争的当前状态、事件真实性或投资方向作事实判断。

## 5. 行情与个股工作台需求

### 5.1 搜索与个股摘要（MKT-01）

- 按代码、名称、拼音首字母搜索；结果明确交易所和证券类型。
- 展示最新价、涨跌幅、OHLC、成交量、成交额、换手率、行业及风险标签；无权限字段明确显示不可用。
- 展示来源、行情时间、入库时间和“实时/延迟/盘后/历史/演示”状态。
- 未接入真实数据时允许开发演示，但必须醒目标识，且不能与真实回测混用。

### 5.2 K 线与分时（MKT-02）

- 支持 1/5/15/30/60 分钟、日/周/月线，支持拖动、缩放、十字光标、区间选择和向前加载。
- 支持不复权、前复权、后复权；显示当前模式和复权锚点，切换后重新计算受影响指标。
- 支持 MA、EMA、成交量、MACD、RSI、布林带；指标参数可修改并保存个人偏好。
- 分时图显示当日价格和累计成交额/累计成交量计算的均价；无法取得所需字段时不展示伪造均价。
- 最新未完成 K 线可动态更新，但以明确样式标为“形成中”；默认不参与可执行策略信号。
- 买卖标记区分“条件触发”“模拟委托”“模拟成交”，点击展示策略版本、触发值与成交约束。
- 支持公告和宏观事件标记；同一日多个事件聚合展示，避免遮挡价格。
- 休市、午休、停牌、历史缺失、网络断开分别显示状态，不用零价补齐图表。
- 形成 60 分钟等聚合线时按交易所会话定义固定分桶，不跨午休拼接，不用自然整点随意切分；供应商口径与平台口径应一致并可追溯。

### 5.3 自选和候选列表（MKT-03）

- 自选分组、备注、批量导入导出；点击股票立即联动图表。
- 选股结果包含排名、得分、信号时间、对应周期、行业、命中条件和不可交易原因。
- 同一股票由多个策略选中时分别保留来源，不把重复出现自动解释为更高胜率。

## 6. 前台策略配置

### 6.1 策略组成（STR-01）

一个策略由以下部分组成：

1. 股票池：市场、板块、行业、自选组、历史指数成分或手工列表。
2. 基础过滤：上市天数、风险警示状态、停牌、流动性、可用数据；条件按当时状态判断。
3. 市场环境：国内趋势、海外风险指标、宏观事件及数据新鲜度。
4. 选股逻辑：条件过滤或多因子评分；两者可组合。
5. 入场与退出：触发周期、条件、调仓频率、持有期限。
6. 仓位风控：最大持股数、单股上限、行业上限、总仓位、现金保留、止损止盈。
7. 执行假设：成交时点、费用、滑点、成交量参与上限、未成交处理。

条件编辑器采用“字段 + 运算符 + 值/字段”的方式，支持 AND/OR 条件组。首版允许两层嵌套，并支持上穿、下穿、连续 N 根成立等明确时间语义。前台展示规则自然语言预览。

### 6.2 参数、校验与版本（STR-02）

- 参数显示单位、有效范围、默认值和说明；百分比与小数值不得混淆。
- 均线短周期必须小于长周期；权重、仓位上限和指标所需历史长度需要校验。
- 用预设结构表达式保存规则，前后端共同校验，不直接执行输入的 JavaScript/Python 文本。
- 操作包括保存草稿、复制、试运行、创建版本、启用、暂停、归档、导入导出。
- 已用于回测或模拟的版本不可覆盖；修改生成新版本，旧信号继续指向原版本。
- 配置不完整、数据权限不足、缺失会影响判断的数据时，应指出具体条件及处理方式。
- 修改已启用策略后先保存为新版本，经用户点击启用才影响后续信号；既有持仓默认沿用其入场版本的退出规则，切换管理版本须主动操作并留痕。

### 6.3 第一版策略模板（STR-03）

| 模板 | 基础逻辑 | 前台可调项 |
| --- | --- | --- |
| 趋势跟随 | 短均线上穿长均线，结合成交量与大盘状态过滤 | 均线窗口、量能阈值、调仓周期、退出方式 |
| 动量轮动 | 按过去 N 个交易日收益排名，限制波动与行业集中度 | 回看窗口、持股数、行业上限、换手周期 |
| 均值回归 | 价格偏离均线或指标进入阈值后触发 | 偏离幅度、RSI 窗口、最长持有期 |
| 全球风险过滤 | 为任一基础策略叠加海外市场/宏观风险约束 | 指标、阈值、有效时段、仓位系数 |
| 分钟趋势确认 | 在已完成分钟线确认突破，并结合最近已完成日线状态 | 分钟周期、突破窗口、量能阈值、日线过滤 |

模板仅用于验证系统能力，不表达收益承诺。财务因子作为扩展插槽；只有取得可追溯披露时间的数据后，才纳入正式历史回测。

### 6.4 跨周期和组合规则（STR-04）

- 日线收盘后产生的结果默认最早在下一可交易时点执行。
- 分钟策略读取最近已完成的日线，不能读取当天尚未完成的日收盘价。
- 多策略争用资金时，使用明确的优先级或固定资金分配；同一时点先处理卖出，再按稳定排序处理买入。
- 总仓位约束优先于单策略目标仓位；冲突和被截断数量在结果中可见。
- 止损只是触发条件，实际卖出仍受可卖数量、停牌和成交约束影响。

## 7. 全球联动、政策与地缘事件

### 7.1 第一版观察清单（GLB-01）

| 分类 | 指标候选 | 用途 |
| --- | --- | --- |
| 国内市场 | 上证、深证成指、沪深300、中证500、创业板、科创50 | 基准与市场环境 |
| 海外权益 | 标普500、纳斯达克相关指数、恒生及恒生科技 | 海外风险偏好、科技链观察 |
| 利率与汇率 | 美国国债收益率、美元指数、美元兑人民币 | 资金成本与汇率环境 |
| 商品与波动 | 原油、黄金、铜、VIX | 能源冲击、工业需求、波动环境 |
| 宏观政策 | FOMC、CPI、就业、关税与制裁相关政策 | 已公布信息和事件日历 |

这是指标候选清单，不代表某个供应商提供全部品种。P0 必须接入国内基准及海外权益、利率或汇率、商品三类代表指标；逐项记录现货/期货、币种、报价单位、频率和延迟。无法接入的指标必须标为不可用，不以不同含义的代理品种无提示替换。

### 7.2 共振分析（GLB-02）

- 对收益率或变化量计算滚动相关，默认提供 20/60/120 个有效观察窗口，并显示有效样本数；不直接对价格水平计算并宣称存在联动。
- 支持按经济时间顺序比较前后 1～3 个交易时段的关系，图表明确正负滞后的定义。
- 比较基础策略和叠加全球过滤后的收益、回撤、交易数、换手与错失机会。
- 默认每个 A 股交易日绑定其决策时点之前最近已完成的海外交易时段；缺少新海外时段时标明沿用及年龄，相关分析默认不重复计入同一个海外时段。
- 同步反应与预测因子分开展示；相关关系不自动解释为因果或持续可预测性。
- 海外数据尚未公布时只能使用最近已知版本；休市与夏令时通过市场日历和时区转换处理。

### 7.3 事件台账与影响规则（EVT-01）

事件字段：标题、类别、国家/地区、发生时间、首次发布时间、系统获取时间、来源链接、核验状态、修订历史、关联资产、影响假设、有效期。

支持三种状态：已核验事件、待核验信息、用户假设情景。假设情景只能进入情景分析，不与真实历史事实混合回测。人工补录和 AI 提取均保留来源及操作记录。

影响规则必须由用户配置或选择模板，采用“事件/市场指标 → 传导渠道 → 行业/个股暴露 → 策略动作”的结构。例如：

| 观察或事件 | 待验证的传导假设 | 可配置动作 |
| --- | --- | --- |
| 美国利率路径变化 | 折现率或风险偏好变化 | 降低/提高某策略仓位系数 |
| 关税政策调整 | 出口需求、成本或供应链变化 | 调整具有相应业务暴露的股票评分 |
| 冲突升级与原油上涨 | 能源供应与运输成本冲击 | 针对相关暴露设置评分或新开仓限制 |
| 制裁、航运受阻 | 供应、交付周期或运价变化 | 增加风险标签，触发观察提醒 |

不能把“战争”统一设为某行业必涨或必跌；映射需说明行业分类、个股业务暴露依据及适用日期。业务暴露无法确认时，只做观察标记。

### 7.4 风险覆盖层（EVT-02）

- 基础策略产生候选和目标仓位，风险覆盖层再施加仓位上限、新开仓限制或评分调整。
- 每个规则可设权重、启停、有效期和衰减方式；默认固定权重加到期失效，复杂衰减后续增加。
- 每条结果展示触发指标、数据时点、阈值、作用范围及调整前后仓位。
- 多事件合并或去重有明确规则；首版仓位系数取有效规则中最保守值，不对重复新闻无限叠加惩罚。
- 缺失/过期输入默认阻止依赖它的新开仓，并提示受影响策略；不得在数据缺失时自动推断事件结束或清仓。
- 官方公布值与市场一致预期区分；没有合法可用的历史预期数据时，不提供“超预期幅度”回测。
- 仅能按日期获知的公告/事件，采用保守的下一交易时点可用假设，并标记时间精度。

## 8. 回测与模拟组合

### 8.1 回测输入与输出（BT-01）

输入：策略版本、起止区间、股票池及其历史成分、初始资金、基准、交易周期、调仓计划、费用模型、滑点、成交量参与上限、复权与缺失数据政策。

输出：累计收益、年化收益、基准收益、超额收益、最大回撤、波动率、夏普比率、胜率、盈亏比、换手率、交易次数、成本分解、持仓集中度、现金占比、逐笔信号/委托/成交及拒绝原因。

报告同时提供净值曲线、回撤曲线、分年/月表现、持仓和行业分布；不足一年时提示年化指标敏感性。年化频率、无风险利率、超额收益计算方式须披露，分钟回测默认聚合成日净值后计算可比风险指标。

### 8.2 A 股撮合约束（BT-02）

- 股票默认按 T+1 约束管理可卖数量；分钟级信号不等于允许当日买入后卖出。
- 交易日历、竞价/连续交易时段、申报数量、最小变动单位、涨跌停、风险警示和新股特殊规则，均按市场、板块、证券及生效日期配置。
- 停牌不成交；成交数量不超过资金、可卖数量、申报单位及成交量参与上限。
- 日线默认在次一可交易日开盘尝试成交；完成分钟线的信号默认在下一根可交易分钟线开盘尝试成交。
- 首版采用保守撮合：一字涨停不买入、一字跌停不卖出；其他触及涨跌停的成交按明确限制处理。仅有 OHLCV 时不能精确重建排队，结果注明近似假设。
- 止损止盈在跳空时按实际可交易价格模型执行，不保证以阈值价成交。若同根线同时触发两者而无法判断先后，采用预先声明的保守顺序并标记。
- 未成交委托首版当次执行窗口结束即撤销；下一时点须按策略重新生成，不能默认持续有效至有利价格。
- 交易手续费、最低费用、卖出相关税费等可配置且按生效日期管理；参数来源记录在回测快照中。
- 成交及现金账使用不复权价格，除权除息通过独立公司行为账调整现金与股数；复权序列用于指标研究并固定锚点，不以复权价格直接撮合。
- 未实现某项证券规则或公司行为时，应限制适用范围并提示，不能默默使用通用股票规则。

上交所规则说明证券回转交易与申报等存在具体约束；实现应按当期适用文本和历史生效时间建模，而非把某组比例永久写死。[上交所交易规则（2026 年修订）](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml)

### 8.3 防止研究偏差（BT-03）

- 每个输入记录业务发生时间、发布时间和系统可用时间；回测只读取决策时点已可用的数据版本。
- 财报按实际披露可用时点使用，宏观指标按当时发布版本使用，不能用最新修订值回填过去。
- 美国当日收盘数据不能被用于此前已结束的 A 股交易时段。
- 股票池须包含当时上市及后来退市的股票；使用当前成分回测历史时，必须标注幸存者偏差，不得称为严格历史股票池回测。
- 预热区间不计入收益；不足窗口的指标显示不可用，不用零值代替。
- 训练、验证、测试区间按时间拆分；首版至少支持样本内/外分割，并记录试验参数和次数。
- 每次运行保留策略版本、引擎版本、数据快照 ID、规则与费用版本及随机种子（如使用随机过程），支持复现与导出。
- 缺少历史事件发布时间、宏观旧版本或完整成分时，报告明确标记“探索性分析”；不得将其与严格时点回测混称。

FRED 官方区分当前可见历史与过去时点已知历史，并提供相应时间参数；这支持本产品要求保存宏观数据版本。[FRED 实时历史区间说明](https://fred.stlouisfed.org/docs/api/fred/realtime_period.html)

### 8.4 模拟持仓与提醒（SIM-01）

- 建立独立模拟账户，记录现金、持仓、成本、公司行为、已实现和未实现收益。
- 区分模拟账户与用户手工录入的真实持仓，真实记录不自动产生券商委托。
- 模拟成交复用回测的策略解释和执行约束，不能直接按信号价记账。
- 提醒包含股票、策略版本、周期、触发时间、原因、数据年龄；去重键包括策略版本、股票、周期和信号时间。
- 同一任务重试不得重复成交或重复发送提醒；异常处理和补算均保留记录。
- 第一版仅站内提醒。短信、邮件或其他渠道由用户以后主动配置。

## 9. 数据需求与采购边界

### 9.1 覆盖和容量目标

| 数据 | 第一版目标 | 边界 |
| --- | --- | --- |
| A 股日线 | 沪深市场，目标最近 10 年，包含证券生命周期与公司行为 | 新上市股票按实际历史；缺失可见 |
| A 股分钟 | 首版至少支持同时监控 100 只股票；按需加载个股历史 | 默认分钟回测上限 100 只、60 个交易日；容量可配置 |
| 全球指标 | 接入清单中的代表指标，日线为基础 | 盘中指标若无相应权限，按实际频率显示 |
| 事件与宏观 | 官方日历、宏观发布、手工可追溯事件 | 全量历史新闻和一致预期非默认免费能力 |
| 基础资料 | 上市退市、交易日历、历史状态、复权因子 | 历史行业/指数成分按供应商实际能力标注 |

100 只与 60 日是首版容量验收基线，不是永久架构上限。若数据采购无法满足，需调整范围记录并由用户选择；仅提供演示不能视为分钟级正式交付。

### 9.2 数据源方案

采用数据适配层，避免业务逻辑绑定某个接口。第一版先选定一个 A 股主源、一个全球/宏观主源，以及手工事件导入路径。

| 方案 | 适用 | 明确取舍 |
| --- | --- | --- |
| 低成本研究 | 日线、有限股票池、允许明确延迟的分钟观察 | 验证权限与稳定性；不可将延迟数据称为即时行情 |
| 稳定盘中 | 有授权和明确服务能力的实时/历史分钟供应商 | 支付数据费用；验证调用频率、并发、历史长度及个人使用范围 |

候选 A 股研究源包括 Tushare 等；分钟权限、实时权限、历史覆盖和费用分别核验，不将日线权限等同于实时分钟权限。官方提供复权因子和实时分钟接口文档，但这些文档不代表用户已取得相应权限。[复权因子](https://tushare.pro/document/2?doc_id=28)、[实时分钟接口](https://tushare.pro/document/2?doc_id=374)

宏观日历优先使用官方发布安排；例如美联储议息日历和 BLS CPI 日历。官网可读页面不一定等于稳定 API，接入方式、允许频率和失败回退需在开发前验证。[美联储日历](https://www.federalreserve.gov/monetarypolicy/fomccalendars.htm)、[BLS CPI 发布日程](https://www.bls.gov/schedule/news_release/cpi.htm)

数据源采购前记录：价格、权限、缓存/历史存储范围、允许展示方式、数据延迟、覆盖品种、国内网络可用性。本文不承诺固定供应商价格，预算暂列待定。

### 9.3 数据质量（DATA-01）

- 统一证券标识、时区、成交量与成交额单位、币种、时间戳和 K 线起止定义。
- 原始数据、标准化数据、计算结果分别保存，并保留来源与转换版本。
- 校验重复记录、负成交量、OHLC 关系、交易日缺口、异常变动和公司行为对应关系。
- 缺失与休市区分；不跨市场静默补零或无限前值填充。
- 数据源故障时展示最后成功数据和过期状态；默认不以过期数据触发新的开仓信号。
- 若切换来源，记录生效时间及差异；不得悄悄拼接不同复权或报价口径。
- 运行任务可增量同步、重试、取消和补算；不在每次打开图表时重新下载全部历史。

## 10. 非功能要求

以下是选定数据源与部署环境后用于验收的目标，不是未经测量的性能承诺。

| 类别 | 首版标准 |
| --- | --- |
| 图表体验 | 固定验收环境下，已有缓存的单股 2,000 根 K 线首次可交互时间 P95 ≤ 2 秒；加载不冻结页面 |
| 策略交互 | 本地配置校验及保存 P95 ≤ 1 秒；长任务异步执行 |
| 分钟信号 | 数据源到达后到信号入库 P95 ≤ 10 秒；行情本身延迟另算并显示 |
| 日线同步 | 数据源确认发布后目标 30 分钟内完成增量更新；前台显示进度及失败原因 |
| 回测任务 | 10 秒内返回任务 ID；支持排队、进度、取消；记录固定规模基准耗时后确定执行 SLA |
| 可靠性 | 同步、信号和模拟成交幂等；重启后任务可恢复或明确失败 |
| 隐私 | 单用户访问控制；数据令牌只在后端，日志和导出默认脱敏 |
| 备份 | 每日备份策略、事件、笔记和模拟账本；行情可重建；首版完成一次恢复演练 |
| 可观测性 | 记录源延迟、数据缺口、任务耗时、失败、信号与成交链路 |
| 设备 | 优先支持 1440×900 及以上桌面；较窄窗口可折叠侧栏；移动端先支持浏览 |

验收时固定机器规格、浏览器、网络、样本集及缓存状态，建议在 4 核/16 GB 环境进行基线测量；性能不足时先测瓶颈，再决定扩容。

## 11. 技术实现建议（供后续 Codex 评估）

技术选型服务于需求，具体版本在开发时核查并锁定。

- 前端：TypeScript 和组件框架；图表采用可接入自有数据的金融图表库，策略编辑以结构化表单为主。
- 图表候选：TradingView Lightweight Charts。它是图表组件，行情需自行接入，指标、事件和策略面板需自行实现；遵循其开源许可及署名要求。[官方仓库与许可说明](https://github.com/tradingview/lightweight-charts)
- 计算后端：Python 服务承载指标、策略解释、回测和数据适配；所有决策逻辑集中于共享引擎，保证回测与模拟一致。
- 任务进程：独立于浏览器运行数据更新、盘中计算和回测；网页关闭后仍按部署环境保持运行。
- 数据存储：关系数据库保存配置、事件和账本；列式文件或分析型存储保存较大行情快照；按实测容量决定是否增加专用时序设施。
- 接口：图表和报告走查询 API，实时状态采用 SSE/WebSocket 或受限轮询；所有第三方令牌留在服务端。
- 第一阶段建议本机或个人服务器部署。若本机休眠/关机，盘中监控不可用，界面须显示心跳和运行状态；需全天运行时再使用常开主机。
- 网站前端可以后续单独托管；分钟数据采集、Python 回测和持续调度需要能运行对应进程的环境，不能仅凭静态网站托管假设全部需求已满足。

本需求阶段不注册站点、不发布网站、不购买数据。后续开发先做数据接入验证，再决定部署形式。

## 13. 验收用例

| 编号 | 操作或场景 | 通过标准 |
| --- | --- | --- |
| AC-01 | 搜索并打开任一支持股票 | 正确标识市场，显示真实来源及更新时间，进入对应图表 |
| AC-02 | 切换周期、复权和指标 | 至少支持 1/5/15/30/60 分钟与日/周/月；数值口径一致，指标重算正确 |
| AC-03 | 从候选、事件和回测交易跳转 | 到达正确个股及时间，标记解释可见 |
| AC-04 | 修改均线和风控参数 | 无需改代码；不合法配置明确报错；合法配置生成新版本 |
| AC-05 | 对比新旧策略回测 | 同一输入版本可复现；参数差异、成本、样本外结果可见 |
| AC-06 | 运行分钟策略 | 已完成分钟线才产正式信号；下一可交易线撮合；延迟和源年龄可见 |
| AC-07 | 当日新买股票触发止损 | 可卖数量不包含当日新买；不能虚构当日卖出 |
| AC-08 | 遇到停牌、涨跌停或资金不足 | 按限制不成交/部分成交，原因与数量可追溯 |
| AC-09 | 放入 A 股收盘后才公布的海外信息 | 不影响之前的 A 股决策；夏令时和海外节假日对齐正确 |
| AC-10 | 修改或晚录入一条地缘事件 | 不倒灌到历史已知信息；假设情景与真实历史报告分开 |
| AC-11 | 触发全球风险规则 | 显示数据、阈值、有效期及调整前后仓位；可关闭并对照 |
| AC-12 | 数据缺失、过期或源断开 | 明确状态，阻止依赖它的新开仓；不以旧数据伪装实时 |
| AC-13 | 任务重试或服务重启 | 不重复生成同一成交/提醒；可恢复或准确报告失败 |
| AC-14 | 验证公司行为与复权 | 分红送股账与股数/现金变化正确；切换显示复权不改变已保存成交账 |
| AC-15 | 使用历史股票池 | 历史成分和退市状态正确；不完整时报告披露偏差 |
| AC-16 | 性能与恢复 | 达到固定环境下的图表、任务响应基线，备份可恢复 |

验证采用固定、可手算的小型行情和公司行为样本，覆盖关键规则；再用真实数据对照数据源和图表。真实性、撮合及跨时间可用性检查优先于页面按钮数量。

## 14. 交付阶段与完成定义

### 阶段 A：需求和数据验证

交付：本 PRD、数据源对照表、小规模真实样本、分钟延迟/历史覆盖/权限测试、部署方案。

通过条件：确认日线、分钟、全球代表指标的获取路径与成本。缺少分钟权限时可以继续做界面和引擎，但分钟能力仍列为未交付。

### 阶段 B：行情工作台与策略配置

交付：搜索、自选、K 线/分时、指标、配置编辑器、策略版本、数据健康页。

通过条件：完成 AC-01～04、AC-12；关键页面使用真实样本验证，演示数据独立。

### 阶段 C：回测和全球风险覆盖

交付：日线与受限股票池分钟回测、报告比较、全球对齐、事件台账、风险规则解释。

通过条件：完成 AC-05、AC-07～11、AC-14～15；已披露数据局限。

### 阶段 D：盘中运行与个人试用

交付：分钟调度、站内信号、模拟组合、重试恢复、备份、操作说明。

通过条件：完成 AC-06、AC-13、AC-16；至少连续 5 个 A 股交易日运行，核对缺失、延迟、重复信号及账本一致性。

**首版完成定义：阶段 A～D 均完成，日线与分钟能力均通过验收；日线先跑通只是中间里程碑。** 不预先给出未经数据验证的固定工期；Codex 开发时按阶段拆任务，并将尚未接入的数据和未实现的证券规则持续列出。

## 15. 待确认事项与默认决策

| 问题 | 暂定方案 | 对实施的影响 |
| --- | --- | --- |
| 数据预算 | 同时保留低成本和稳定盘中两档 | 决定分钟权限、延迟、历史长度和新闻覆盖 |
| 部署地点 | 本机优先，预留个人服务器部署 | 决定后台常开能力与远程访问方式 |
| 主要交易风格 | 波段/日线研究与分钟确认并存 | 决定模板优先级，不影响双频能力 |

| 初始策略 | 趋势、动量、均值回归及全球风险过滤 | 作为功能样例，用户可删除或修改 |
| 执行方式 | 回测、模拟及手工记录持仓 | 不引入券商自动下单依赖 |

以上默认值用于使需求可拆解，不代表已采购数据、已确认交易偏好或已授权实盘。后续确认意见进入修订记录，不静默改变第一版验收范围。

## 16. 后续 Codex 实施起始任务

1. 读取本需求书，创建需求编号到开发任务和验收项的映射。
2. 先核验选定数据源在当前网络、权限与预算下的日线/分钟/宏观样本；输出覆盖及缺口。
3. 固定证券标识、交易日历、数据时间语义、策略版本和数据快照契约。
4. 建设行情与策略配置的最小闭环，再接入共用策略引擎和保守撮合。
5. 将全球因子与事件作为可关闭、可解释、可单独对照的覆盖层接入。
6. 完成分钟调度、模拟账本及连续运行验收，交付启动说明、数据限制和恢复方法。

开发过程中遇到数据权限缺口应准确记录，不以演示数据、静态截图或无法运行的占位按钮宣称需求完成。
